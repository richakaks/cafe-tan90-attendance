# Cafe Tan90 Attendance — setup guide

This turns into a small web app hosted by Google (no separate server, no cost). Once it's deployed, it lives at a permanent URL you can bookmark or pin as a shortcut on the shared device.

## What you're setting up

One URL, one page, two tabs at the top:

- **Staff view** (the default tab) — Miw, Nureen, and Richa share this on one device. Each taps their name's "Log in" / "Log out" button, and "Mark done" on each task as they finish it.
- **Admin view** (click the tab, no separate link to remember) — PIN-protected: whoever clicks it still hits a lock screen and needs the PIN before anything admin-related shows. Once unlocked there are two sub-tabs: **Tasks** — one task list per date (check or edit any day, not just today's), mark any task to repeat automatically on chosen days of the week, drag tasks into whatever order looks best, plan one-off tasks across a whole week or month ahead of time (with a calendar you can click to preview or jump to any day you've already planned), manage the employee roster, and jump straight to the raw Google Sheet — and **Payroll** — set each employee's hourly rate (with the date it starts applying) and see exact-hours pay for any day or browse any month's total.
- **Google Sheets backend** — every log-in/out and every "Mark done" writes straight into a Google Sheet. No manual export, ever. A new spreadsheet is created automatically the first time anyone uses the app in a new calendar month, named "Cafe Tan90 Attendance — <Month Year>" (e.g. "Cafe Tan90 Attendance — August 2026"), with one tab per day of that month (28-31 tabs) — each tab holding that day's attendance log, task assignments, and task-completion times. One document per month, so a month's worth of pages all live in one place.

## How the automation actually works (the questions you asked)

**"How is a day marked done, and how is it known that it's done?"**
There's no button for this and nothing to remember — it's automatic, driven purely by the calendar date. Every action (log in, log out, mark done, viewing the Staff page) always reads and writes whichever day-tab matches *today's* date in Bangkok time. There's no separate "close the day" step because a day doesn't need to be explicitly closed — it just accumulates whatever happened on it. If you want a human-readable sense of whether a day is "finished," that's just: did everyone log out, and are all their assigned tasks showing a green "Done" pill? You can see that at a glance on the Staff page or by opening the day's tab in Sheets — but nothing needs to be marked or triggered.

**"How does tomorrow's page show up? What about next month's?"**
It already exists before you need it. The moment the app is used for the first time in a given calendar month, it builds the *entire* month's spreadsheet up front — every day tab for that month, pre-created, sitting there ready. So "tomorrow's page" (or "next month's doc") isn't something that gets created at midnight or by a trigger; it was already sitting there from the first use of the month. The only thing that happens automatically at a date rollover is that the Staff page starts *reading and writing* the next tab instead of today's — because "today" is just computed from the clock, not stored anywhere. (The very first time the app is opened in a new month, building all 28-31 tabs takes a few extra seconds — after that it's instant for the rest of the month.)

In short: nothing to schedule, nothing to press. Open the Staff page any day, any month, and it's already on the right page.

## One-time setup (about 5 minutes)

1. Go to **script.google.com** and sign in with the Google account you want to own this (this account's Drive is where the monthly spreadsheets will live).
2. Click **New project**.
3. Rename the project (top left) to something like "Cafe Tan90 Attendance".
4. You'll see a default `Code.gs` file already open — delete its contents and paste in the contents of **Code.gs** from this bundle.
5. Add the HTML files: click the **+** next to "Files" → **HTML** → name it exactly `Staff` (Apps Script adds `.html` itself) → paste in **Staff.html**'s contents.
6. Repeat step 5 for `Admin` (paste **Admin.html**) and `Stylesheet` (paste **Stylesheet.html**).
7. Open **appsscript.json**: click the gear icon (Project Settings) on the left, tick "Show `appsscript.json` manifest file in editor", then open it from the file list and replace its contents with the **appsscript.json** from this bundle.
8. **Set your admin PIN**: in `Code.gs`, find the `setAdminPin` function near the bottom, change `'2468'` to whatever PIN you want, then select `setAdminPin` from the function dropdown at the top and click **Run** once (it'll ask you to authorize — that's normal, click through it since this is your own script). That's the only time you need to run anything manually.
9. Click **Deploy → New deployment**.
   - Click the gear next to "Select type" and choose **Web app**.
   - Description: anything, e.g. "v1".
   - Execute as: **Me**.
   - Who has access: **Anyone** (this lets the shared device use it without anyone signing into a Google account — appropriate since it's one shared screen).
   - Click **Deploy**, then **Authorize access** and click through the Google warning (it's your own script, this is expected for personal Apps Script projects).
10. Copy the **Web app URL** it gives you. That's the only link there is — open it once to confirm it loads, shows today's date with Miw/Nureen/Richa, and has "Staff view" / "Admin view" tabs at the top.
11. Bookmark that one URL on the shared device (or add it to the home screen if it's a tablet/phone) so staff never have to type it. Clicking "Admin view" still requires your PIN, so it's safe to leave that tab visible.
12. Optional: if you personally want a bookmark that opens straight into the Admin tab (skipping the click), add `?page=admin` to the end of the same URL, e.g. `https://script.google.com/macros/s/XXXXXXXX/exec?page=admin`, and bookmark that separately for yourself. It's still the exact same page and still PIN-gated — the query string just pre-selects the tab on load.

## Using it day to day

- **Staff:** open the Staff page link (or it's already sitting there on the shared device). First, identify yourself: pick your name from the "Who are you?" box at the top and enter your PIN, then **Continue**. Until you do, every row on the page — including your own — is visible but greyed out and un-tappable; that's on purpose, so nobody can accidentally (or deliberately) log someone else in or mark someone else's task done. Once you're identified, your own row lights up and its buttons become tappable — everyone else's stays greyed out. Tap "Log in" when you arrive, "Log out" when you leave, and "Mark done" on each task as you finish it (only shows up once you're assigned it and logged in). If a device is shared or you're on someone else's phone, tap **Switch user** (next to your name at the top) when you're done, or when it's the next person's turn — nothing is remembered between sessions, so the page always asks again rather than staying signed in as you. Made a mistake — tapped Log in/Log out or Mark done by accident? As long as it's the same day, you can undo it yourself right next to the button; it just clears the tap; only the admin can type in a specific corrected time (see below). Tap **My hours & pay** (next to Switch user) to see your own log-in/out times and pay for today or any past day, plus the month's running total — this view only ever shows your own numbers, never anyone else's. You can also change your own PIN there. If you ever forget your PIN, the admin PIN also works to identify as anyone — ask whoever holds it.
- **Admin — Tasks for [date]:** this is the one place you manage tasks, and it can point at any day, not just today — use the **‹ Prev day** / **Today** / **Next day ›** buttons (or the date picker) above the table to move around. Add a task, tick who's doing it, and if it needs to repeat — "Make base milk," "Clean all counter tops," "Sweep the floor" — click its **Repeats** chip, then tick the days of the week it happens on, or use the **Weekdays** / **Daily** shortcut buttons to check Mon–Fri or all 7 days in one click, then click **Done**. From then on that task shows up automatically on every matching day, forever — nothing to re-add. A task without any days ticked is just a one-time task for that day. Drag a row by its **≡ handle** on the left to reorder tasks however reads best — first, last, wherever — this is purely visual ordering and has no effect on repeats or assignments. Editing who's doing a repeating task on one specific day only changes that day — the repeat rule, and every other day, is untouched; unticking every day in its Repeats editor stops it from being added to *brand-new* days going forward (days that already picked it up, including future days already built this month, keep it as-is — same as removing an employee doesn't erase their past attendance). Nothing on this whole card is saved until you click **Save tasks** at the bottom — that one click also applies any Repeats changes you made, any reordering, and any task list you brought in with **Copy previous day's tasks** (which only stages that day's tasks into the editor; it doesn't touch the Sheet until you click Save). This is also how you check that something you planned ahead actually landed — switch to that date and look, or see below. Typing a task name (here or anywhere else on the Admin page) automatically capitalizes the first letter of each word once you tap away or move to the next field — "clean the counter" becomes "Clean The Counter" — so nobody has to think about it.
- **Admin — planning one-off tasks ahead:** for something that doesn't repeat forever — a one-time deep clean, an extra task just for a busy weekend — the **Plan tasks ahead** card lets you set it up once and drop it onto a range of days in one go, without it becoming a repeating task. Dates that already have tasks show a small dot; **click any date on the calendar to preview what's on it** — e.g. click next Monday to see "Sofa cleaning · Nureen" right there, with an **Edit this day in Tasks above** button to jump straight to it. To add something new, tap dates to select them (or use the **Today** / **Rest of this week** / **Next 7 days** / **Rest of this month** shortcuts), type the task name, tick who's doing it, then **Add task to selected dates**. This one **saves immediately** the moment you click Add — there's no separate save step, so if you navigated away right after, it's already on the Sheet. It writes straight onto each of those days' own tab — including tabs in a future month, which get pre-built on the spot the first time you plan into a new month. It layers on top of whatever's already on a given day (if that day already has a task with the same name — including a repeating one — it just adds the new assignments to it rather than duplicating). There's no cap on how many tasks a day can hold, so nothing ever gets skipped for being "full."
- **Admin — employees:** the admin page has an **Employees** section — type a new name into the box next to anyone's row to rename them (auto-capitalized as you type, same as tasks), tap **+ Add employee** to bring on a new hire (up to 8 active at once, and you'll be prompted for their starting PIN right there), or tap the **✕** next to someone to remove them. Removing someone doesn't delete anything — their past attendance stays exactly as it was in the Sheet, they just stop showing up on the Staff page and task list from today onward. A rename or add/remove takes a few seconds to apply because it quietly updates every remaining day-tab in the current month so the roster stays consistent for the rest of it (already-past days are left untouched, since that's history). Payroll totals are tracked per person, not per name text, so renaming someone mid-month (or removing and re-adding them) never splits their hours/pay into two separate lines or drops what they'd already earned — a rename shows their new name going forward with all their hours still counted under it. The same section shows a **PIN** column — "Set" or "Not set" for each person, with a **PIN** button to set or reset it (useful if someone forgets theirs, or you're onboarding a new hire without one yet). The admin PIN doubles as a master override everywhere a personal PIN is asked for — on the Staff identify screen or the My hours page — so you can always identify as, or act on behalf of, anyone even if you don't know their personal PIN.
- **Data:** the admin page has an **"Open this month's Sheet"** button that jumps straight to today's tab — no need to dig through Drive. (If you ever do want to browse Drive directly, look for a folder called "Cafe Tan90 Attendance Sheets" with one spreadsheet per month, 28-31 tabs each.) Nothing to export — it's already there, live, as soon as someone taps a button.
- **Admin — Payroll:** click the **Payroll** sub-tab (next to Tasks) at the top of the Admin page. **Hourly rates** lists each active employee with their current rate — click **Change rate** to set a new one, enter the baht/hr amount and pick the date it starts applying (today, backdated, or scheduled ahead — any date works), then **Save**. A rate scheduled for a future date shows as "starting [date]" under that person's current rate and doesn't affect anything until that date arrives; nothing about past pay is ever rewritten when you set a new rate. **Payroll for [date]** shows that day's log-in time, log-out time, exact hours (down to the minute, never rounded to a quarter hour), and pay for everyone, with **‹ Prev day** / **Today** / **Next day ›** to move around. **Month totals** shows the same, summed for a whole month, with **‹ Prev month** / **Next month ›** to look back at any past month or check the current one so far — if a rate changed partway through a month, each day is paid at whatever rate was in effect that day, and the totals reflect that split automatically. If someone's hourly rate is never set, they default to ฿40/hr until you set one.
- **Correcting a missed or wrong log in/out, or a task-done time:** there are two levels of correction, on purpose. An employee can **undo their own same-day tap** — a Log in, Log out, or Mark done they tapped by accident — right from the Staff page, but only for today, only their own, and only as a plain clear (there's no way for staff to type in a specific replacement time). For anything more than that — fixing a wrong time, filling in a punch someone forgot entirely, or correcting any past day — that's admin-only. Since pay comes straight from someone's actual log-in/log-out timestamps, a missed punch is a real pay mistake, not just a display glitch — so **Payroll for [date]** has an **Edit** button on each person's row. Click it to open a small editor right there with a log-in time and a log-out time you can type or clear; leaving one blank means "no punch recorded" for that side. Use it to fill in a punch someone forgot entirely, fix a wrong one, or clear one out completely — for today or any past day (you can't edit a future date, since nobody's worked it yet). Once you save, that row shows a small **(edited)** marker next to the person's name from then on, so it's always visible at a glance that a time was hand-corrected rather than logged normally by the person themselves — the marker never goes away once a field's been touched, even if you edit it again later. If a correction is for today, it also updates that person's Staff-page log-in/out button, since it's the same underlying record. Saving re-checks that log out is after log in (same as a normal shift) and recalculates that day's hours and pay immediately. The same idea applies to task completions: on **Admin — Tasks for [date]**, each assigned person's cell shows their done time (or "Not done") with a small **✎** link — click it to type in a specific completion time or clear it, for today or any past day. Unlike attendance, a task-done correction doesn't get an **(edited)** marker (see the judgment-call note below).
- **Staff task table:** tasks are listed as rows, with the active employees as columns across the top (better than the other way around once there are more than a couple of tasks — nothing to scroll sideways through). Each person's column shows their present/not-in-yet status in the header, and fades until they've logged in.

## If you ever want to change something later

- **Add/remove/rename employees:** no code changes needed — do this from the Admin page's Employees section (see above).
- **Change the PIN:** edit and re-run `setAdminPin` in the script editor — no redeploy needed.
- **Tasks per day:** no cap — add as many as a day needs on the "Tasks for [date]" editor. (Employees are a separate, fixed cap of 8 — see below — since each one needs a permanent column on every day tab; raise `MAX_EMPLOYEES` in `Code.gs` if you ever need more than 8.)
- **Every code change needs a new deployment version** to go live: Deploy → Manage deployments → pick the pencil/edit icon → Version: **New version** → Deploy. Just saving the file in the editor is not enough on its own.

## A couple of judgment calls I made — flag if you'd rather have it differently

- **"Who has access: Anyone"** means no Google login is required on the shared device — this matches "staff should think as little as possible," but it also means anyone with the URL could open it. If that's a concern, we can switch to "Anyone within [your Workspace domain]" if you're on Google Workspace, or add a lightweight PIN gate to the Staff page too.
- **Employee cap is 8** — plenty of headroom for a small cafe team, but if you ever expect to grow past that, say so and I'll raise the limit before you deploy.
- **Removing an employee mid-shift** (after they've already logged in today) will still blank their name on today's tab going forward from that point — their already-logged in/out times for today stay in the row, just without a name label next to them until you look at row position. This is a rare edge case (removing someone typically happens when they've left for good, not mid-shift), but flagging it in case it matters to you.
- **Present Today never un-checks on log-out** — once someone logs in, they're marked present for the rest of the day even after logging out. That's usually what "present today" should mean, but say the word if you want it to reset.
- **Log in/out and Mark done are all one-shot per day** — the buttons disable themselves once used, so nobody can double-tap and overwrite a time by accident. If someone needs to correct a mistake, they can undo their own same-day tap right from the Staff page (see above), or an admin can fix any time on the Payroll or Tasks pages — no manual Sheet editing needed for either case anymore, though it's always still an option if you prefer it.
- **Staff identity is never remembered on the device, by design** — reloading the page, or tapping **Switch user**, always goes back to the "Who are you?" screen. We went with "always ask" over remembering a phone deliberately: it's what makes a shared device or a borrowed phone work correctly with no extra setup, since nothing is ever tied to a specific device — only to whoever's PIN was just entered.
- **Sheet checkboxes instead of TRUE/FALSE** — the Present Today / Login Edited / Logout Edited columns on each day tab, and the "Assigned" column for each employee on the Tasks table, now render as native Sheet checkboxes instead of raw TRUE/FALSE text. This applies automatically to already-built day tabs too (not just newly-created ones), the next time that tab is touched by the app — nothing to migrate by hand. A row or column that's never actually had anyone in it (a spare employee slot beyond your current headcount) is left fully blank rather than showing an empty, unusable checkbox. If someone is removed mid-shift, their row/column keeps its checkbox and its data even though their name goes blank — nothing about a real day's record ever gets wiped just because the checkbox display logic changed.
- **No dedicated "Undo" button for admin on the Payroll day table** — we discussed adding one alongside the employee-side Undo, and decided against it. The Edit button already covers it (open it, clear a field, Save), and a bare one-click Undo sitting directly on a payroll row felt riskier there than useful — unlike the employee's same-day-only Undo, an admin's version could sit on any past day's already-relied-on payroll data, and a misclick with no confirmation and no visibility of the current value felt like the wrong tradeoff. Left as-is; revisit if it ever feels like a real friction point day to day.
- **Task-done corrections don't get an "(edited)" marker** — attendance edits do (see above), because attendance is what pay is computed from and it matters to be able to spot a hand-corrected time at a glance. Task completion times aren't payroll-critical the same way, so we kept it simple rather than adding a marker column for every employee on every task row. Say the word if you'd rather have that tracked too.
- **A task can only be marked done if that person is assigned it and already logged in** — enforced on the server too, not just hidden in the UI, so it can't be bypassed.
- **Renaming a repeating task** (typing a new name into its row while it still has Repeats set, then Save) updates the repeat rule itself, so brand-new days pick up the new name correctly. The one gap: any day whose tab was already built *before* the rename — which, in practice, is most of the current month, since the whole month's tabs get pre-built the first time anyone uses the app that month — keeps the old name (that day isn't touched retroactively, on purpose, so a hand-edit you made for that specific day is never silently overwritten). If that happens and a day ends up with both the old and new name, just delete the stale one from that day's "Tasks for" editor.
- **No limit on tasks per day, including how many can repeat at once** — each day's tab is a growing list of task rows rather than a fixed set of columns, so there's nothing to run out of room in. (There's one internal detail, not a real-world limit: the script only looks for tasks in the first 400 rows of a day's task list — raise `TASK_ROW_SCAN_WINDOW` in `Code.gs` if a single day genuinely ever needs more than that, which would be extremely unusual for a small team.)
- **Payroll pay is computed from the Sheet's log-in/log-out timestamps directly** (to the second), not from the "Hours Worked" formula column shown on each day tab — they'll normally agree, but if you ever hand-edit a time cell without also touching the formula, Payroll always reflects the actual log-in/out times, which is the more reliable source of truth.
- **An employee's hourly rate defaults to ฿40/hr** until you explicitly set one for them in Payroll → Hourly rates. Change `DEFAULT_WAGE_RATE` near the top of `Code.gs` if you'd rather a different starting default.
- **Reordering tasks by drag is purely cosmetic** — it changes what order tasks display in, nothing about assignments, repeats, or which employee does what. It only takes effect once you click **Save tasks**, same as every other change on that card.
